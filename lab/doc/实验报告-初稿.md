## 1. 任务分析

### 1.1 实验目标

本实验在 MiniOB 框架上补全 SQL 功能，要求理解并实现从语法解析、语义绑定、查询优化与执行到存储与索引维护的完整路径，能够通过编译运行与 SQL 测试验证各功能正确性。

MiniOB 采用 **SQL 解析 → 语句绑定（Stmt）→ 逻辑计划 → 物理算子 → 事务/存储引擎** 的分层结构，与数据库系统原理课程中的查询处理与存储管理内容相对应。

### 1.3 总体技术路线

各项功能统一遵循 MiniOB 标准执行路径，不在旁路单独实现：

```text
SQL 文本
  → 词法/语法分析（lex_sql.l、yacc_sql.y）
  → Stmt 层（表/字段绑定、类型与语义检查）
  → LogicalPlanGenerator（逻辑算子树）
  → PhysicalPlanGenerator（物理算子、子查询 prepare/open）
  → Trx / Table / HeapTableEngine / B+ 树索引
```

设计要点：

- **DDL**（如 drop-table、create index）经 `CommandExecutor` 执行；
- **DML 与 SELECT** 经 Stmt 与火山模型算子执行；
- **子查询**抽象为表达式节点，WHERE 条件与 UPDATE SET 子句共用同一套绑定与执行机制；
- **索引维护**在 INSERT/UPDATE/DELETE 时采用「先删旧索引项 → 修改记录 → 插入新索引项，失败则回滚」策略，保证堆表与 B+ 树一致。

## 2. 环境配置

### 2.1 macOS

#### 2.1.1 开发方式说明

课程指导书提供 GitPod 与 Docker（`oceanbase/miniob` 镜像）两种环境，用于统一 Linux 工具链。本组在 macOS 上采用 **本机编译** 方式，未使用 Docker，理由如下：

1. 通过包管理器安装 cmake、flex、bison 3.x 及 C++ 编译器后，可直接使用 MiniOB 自带的 `build.sh` 完成依赖初始化与编译，与官方流程一致；
2. 本机运行 observer CLI 与自动化测试脚本，调试与回归迭代更直接；
3. 修改语法文件后可在本机立即重新生成解析器并编译，无需容器挂载与端口配置。

使用本机方式时，须保证 **Bison 版本为 3.x**（见下节），并完成 `build.sh init` 对第三方库的安装。

#### 2.1.2 Bison 版本要求

MiniOB 语法文件 `src/observer/sql/parser/yacc_sql.y` 使用 Bison 3 特性（如 `%define api.pure full`）。macOS 系统自带的 Bison 2.3 无法编译该文件，报错例如：

```text
yacc_sql.y:55: syntax error
```

因此需通过 Homebrew 等包管理器安装 **Bison 3.8.x**，并在编译前将其置于 `PATH` 首位，使 `bison --version` 输出 3.x。修改 `yacc_sql.y` 后须重新执行 `bash build.sh debug --make` 以再生 `yacc_sql.cpp`。

#### 2.1.3 安装与编译步骤

1. 安装 Xcode Command Line Tools（提供 clang 编译器）；
2. 安装 cmake、flex、bison（3.x）；
3. 克隆仓库并初始化子模块：`git submodule update --init --recursive`；
4. 初始化依赖：`bash build.sh init`（编译 libevent、googletest、jsoncpp 等）；
5. 编译 observer：`bash build.sh debug --make -j8`；
6. 运行：`build_debug/bin/observer -f etc/observer.ini -P cli`。

主要产物：`build_debug/bin/observer`（服务端）、`build_debug/bin/miniob/db/sys/`（默认数据目录）、`etc/observer.ini`（配置）。

#### 2.1.4 常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| yacc 语法错误 | Bison 版本过低 | 安装 Bison 3.x 并调整 PATH |
| init 阶段 replxx 失败 | 第三方子模块状态异常 | 在 replxx 目录恢复后单独编译安装 |
| 重复测试出现意外 FAILURE | 数据目录残留 | 清空 `miniob/db/sys` 下表文件后重测 |

## 3. 功能实现

### 3.1 basic（2 分）

**功能**：CREATE TABLE、INSERT、SELECT、CREATE INDEX、DELETE 等 MiniOB 基线能力。

**实现**：沿用官方默认实现，作为后续功能的回归基线。

---

### 3.2 drop-table（2 分）

**功能**：`DROP TABLE` 删除表及关联元数据与磁盘文件；删除不存在的表返回 FAILURE；删除后可同名重建。

**实现**：补全 `DropTableStmt` → `CommandExecutor` → `Db::drop_table`，删除堆表文件、索引文件及 catalog 中的表定义。

---

### 3.3 update（2 分）

**功能**：`UPDATE 表 SET 字段 = 值 [WHERE 条件]`，仅支持更新单个字段；支持条件更新与全表更新；存在索引时更新后索引与数据一致。

**实现**：

- 新增 `UpdateStmt`、`UpdateLogicalOperator`、`UpdatePhysicalOperator`；
- `HeapTableEngine::update_record_with_trx`：先删除旧索引项，再修改堆记录，最后插入新索引项；任一步失败则回滚已完成的索引操作。

---

### 3.4 date（2 分）

**功能**：`DATE` 类型；支持 `2020-01-21`、`2020-1-01` 等灵活格式；闰年判断；非法日期（如 `2017-2-29`）插入返回 FAILURE；DATE 列可建索引并正确比较。

**实现**：扩展 `AttrType::DATES` 与日期解析/比较逻辑；词法与语法增加 `DATE` 类型；日期在存储层按整数编码，索引键比较与堆表一致。

---

### 3.5 aggregation-func（2 分）

**功能**：`COUNT、MIN、MAX、AVG、SUM`；支持 `COUNT(*)`；`MIN(*)`、不存在的列等非法写法返回 FAILURE。

**实现**：在 `aggregator.cpp` 中实现各聚合器；无 GROUP BY 的单表聚合通过 `ScalarGroupByPhysicalOperator` 扫表完成。

---

### 3.6 like（2 分）

**功能**：`WHERE 列 LIKE '模式'`，`%` 匹配零个或多个字符，`_` 匹配单个字符，仅支持 CHAR 类型。

**实现**：扩展比较运算符 `LIKE_OP`；独立模式匹配模块实现 `%`/`_` 递归匹配；在 `ComparisonExpr` 求值路径中调用。

---

### 3.7 join-tables（2 分）

**功能**：`INNER JOIN … ON …`；支持多表链式连接、ON 子句中的 AND、以及与 WHERE 的组合。

**实现**：语法层解析 `join_conditions`；`JoinLogicalOperator` 与嵌套循环连接算子 `NestedLoopJoinPhysicalOperator` 在迭代结果时按 ON 条件过滤。

---

### 3.8 function / expression（2 分）

**功能**：标量函数 `LENGTH(字符串)`、`ROUND(浮点)`、`DATE_FORMAT(日期, 格式串)`；参数类型不符时整条语句 FAILURE。

**实现**：`FunctionExpr` 与函数求值模块；语法层支持函数调用表达式；按参数类型分发到对应实现。

---

### 3.9 order-by（2 分）

**功能**：`ORDER BY` 单列或多列排序，支持 ASC/DESC（默认 ASC）；可与 WHERE、JOIN 联用。

**实现**：`SortLogicalOperator` / `SortPhysicalOperator` 收集子算子输出后在内存中排序。

---

### 3.10 group-by（4 分）

**功能**：多列 `GROUP BY`；分组聚合；`HAVING` 对分组结果过滤；与 WHERE、ORDER BY、JOIN 组合。

**实现**：`GroupByLogicalOperator` 与 hash 分组物理算子；HAVING 绑定为聚合后的谓词表达式；校验 SELECT 列表与 GROUP BY 键的合法性。

---

### 3.11 multi-index（4 分）

**功能**：`CREATE INDEX ON 表(列1, 列2, …)` 复合索引；空表/非空表建索引；INSERT、UPDATE、DELETE 后复合索引键正确。

**实现**：`IndexMeta` 支持多字段；B+ 树键按字段顺序拼接编码；DML 路径统一调用索引项插入与删除接口。

---

### 3.12 unique（2 分）

**功能**：`CREATE UNIQUE INDEX`；重复键值插入或建索引时 FAILURE；重复索引名 FAILURE。

**实现**：索引元数据增加 unique 标志并持久化；唯一索引插入前查重，冲突则拒绝操作。

---

### 3.13 simple-sub-query（4 分）

**功能**：`IN / NOT IN (SELECT …)`；标量子查询比较 `(SELECT …) op 列`；子查询内可使用聚合；多行标量子查询、`SELECT *` 子查询返回 FAILURE。

**实现**：

- 引入 `SubQueryExpr`、`InSubQueryExpr`，递归绑定内层 `SelectStmt`；
- 子查询物理计划在 `prepare/open/close_subquery_expressions` 中统一管理；
- 非关联子查询结果可物化缓存；标量子查询限制结果行数为 0 或 1；
- 含子查询的比较表达式不参与谓词下推优化，避免子查询未 prepare 即被执行。

---

### 3.14 complex-sub-query（5 分，困难题）

**功能**：嵌套子查询；关联子查询（内层引用外层列）；子查询中含聚合；关联子查询脱离外层单独执行时 FAILURE。

**实现**：

- `BinderContext` 建立父作用域链，子查询绑定时传入外层上下文；
- 外层列标记为 `outer_ref`，执行时通过外层 tuple 栈读取当前外层行；
- 关联子查询标记 `correlated`，不缓存物化结果，按外层每一行重新计算；
- 嵌套关联时外层 tuple 入栈策略避免内层扫描 tuple 覆盖外层行引用。

---

### 3.15 null（3 分）

**功能**：列定义 `NULL` / `NOT NULL`；插入 NULL 与 NOT NULL 约束校验；`IS NULL` / `IS NOT NULL`；NULL 参与比较的三值语义；聚合函数跳过 NULL（`COUNT(*)` 与 `COUNT(col)` 区分）。

**实现**：

- 字段元数据增加 nullable 属性；
- 记录在堆页内使用 null bitmap 标记空值；
- 读取 tuple 时根据 bitmap 构造 NULL 值；
- 比较表达式与聚合求值遵循 NULL 语义。

---

### 3.16 update-select（4 分）

**功能**：`UPDATE 表 SET 列 = (SELECT …) [WHERE …]`；SET 右值可为子查询或表达式，含标量、聚合与关联子查询；多行更新过程中若某行失败，已更新行语句级回滚。

**实现**：

- 语法与 `UpdateSqlNode` 将 SET 右值改为表达式；
- `UpdateStmt` 通过 `ExpressionBinder` 绑定右值；
- `UpdatePhysicalOperator` 对每条命中行求值、类型转换并写回；失败时逆序调用 `update_record` 恢复。

---

### 3.17 big-write（5 分）

**功能**：大量 INSERT、UPDATE、DELETE 混合操作下系统稳定运行，结果正确，索引与堆表一致；重启后数据仍可读取。

**实现**：

- 加固 DELETE 路径：删除堆记录失败时回滚已删除的索引项，与 UPDATE 策略对齐；
- 通过固定种子的压力脚本模拟 500 行与 2000 行规模的随机写操作，并校验最终行数及重启后持久化。

---

### 3.18 big-query（5 分）

**功能**：较大数据量下 SELECT、JOIN、GROUP BY、IN 子查询等读操作结果正确。

**实现**：在既有查询与索引能力上，通过 800 行规模的压力脚本验证读路径在大批量数据下的正确性。

---

## 5. 总结与结论

### 5.1 工作总结

本实验在 MiniOB 上完成了 **18 项 SQL 功能** 的设计与实现，涵盖 DDL/DML、类型与 NULL 语义、多表连接、聚合与分组、表达式与函数、单列/复合/唯一索引、非关联与关联子查询、带子查询的更新，以及大规模读写场景下的稳健性。其中 **complex-sub-query** 为困难题，涉及作用域绑定与外层行传递，是技术难度最高的模块。

全部功能沿统一的 Stmt → 逻辑计划 → 物理算子路径实现，子查询、NULL、UPDATE 等模块共享表达式框架，结构清晰，便于维护。

### 5.2 实验收获

通过本次实验，完整实践了 SQL 从文本解析到 B+ 树索引维护的数据库实现流程；对查询优化器与执行器的分工、火山模型算子接口、以及索引与堆表同步策略有了具体认识。关联子查询的实现加深了对 SQL 作用域与相关求值的理解。

### 5.3 不足

- 未实现 TEXT、视图、别名等扩展题目；
- 未引入 hash join、向量化执行等性能优化；
- NULL 在部分旧式条件解析路径上功能不完整。

### 5.4 结论

本系统完成了课程要求的 18 项功能开发，并通过官方 primary 用例、100 条综合断言及压力测试验证。在当前测试覆盖范围内，各功能行为符合预期，满足课程设计提交与答辩要求。
