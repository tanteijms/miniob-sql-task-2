## 1. 前端实际做了什么（对照代码）

本课题在 `lab/frontend/` 下实现了一个**零依赖**的本地 Web 演示环境，结构如下：

| 模块      | 文件                          | 作用                                                                                 |
| --------- | ----------------------------- | ------------------------------------------------------------------------------------ |
| HTTP 服务 | `server.js`                 | 托管静态页面；提供 `/api/sql`、`/api/health`、`/api/test-report`、`/api/log` |
| 演示主页  | `index.html` + `app.js`   | 功能按钮、现场 SQL、输出控制台                                                       |
| 演示脚本  | `demos.js`                  | 18 组预设 SQL（basic、null、子查询、压力等），按分组渲染为按钮                       |
| 测试总览  | `tests.html` + `tests.js` | 读取 `lab/test/latest.json` 等本地资产，可视化回归结果                             |

**主页能力（`app.js`）：**

- 右上角通过 `/api/health` 显示 observer 连接状态（绿点 = 已连接）。
- 按 `demos.js` 中的 `group` 字段分组展示 **18 个功能按钮**，点击后 POST `/api/sql`，在下方控制台逐条显示 `SUCCESS` / `FAILURE` / `EXPECTED FAILURE`。
- 顶部工具栏：刷新状态、清空输出、**重置 demo 数据**、**导出 session.log**。
- **现场 SQL 控制台**：4 组推荐脚本（基础建表、NULL、UNIQUE、UPDATE+子查询），可「加载」或「直接执行」；也支持手写 SQL。

**测试总览页能力（`tests.js`）：**

- 通过 `/api/test-report` 汇总 `lab/test/latest.json`、`latest.md` 等，展示：总用例数/通过率、分类覆盖、功能矩阵、慢用例、报告摘录。

因此报告里只需说明两点：**（1）可视化演示 SQL 执行；（2）可视化展示自动化测试结果。**

## 3. 操作步骤（约 5 分钟拍完）

### 3.1 启动（Windows）

```powershell
# 终端 1：Docker 内 observer
docker start miniob-obs-test
docker exec -d miniob-obs-test bash -lc "mkdir -p /tmp/obs-data && cd /tmp/obs-data && /miniob/build/bin/observer -f /miniob/etc/observer.ini -p 6789 -P plain"

# 终端 2：前端
cd F:\Code\20260602_DBomini
$env:OBSERVER_AUTO_START="0"
node lab/frontend/server.js
```

浏览器打开：**<http://127.0.0.1:3001>**

### 3.2 按顺序截图

1. **图 1**：打开主页即可，确认状态栏为「observer 已连接」。
2. **图 2**：点 **`basic`**（首次演示不必点「重置」）；等输出跑完再截图。
3. **图 3**：点 **「测试总览」** → 截取顶部 4 张汇总卡片。
4. **图 4**：返回主页 → 滚到「现场 SQL 控制台」→ 点 **「NULL 语义」** 的 **直接执行** → 截图。
5. **图 5（可选）**：点 **「📥 导出日志」**。

> 注意：若重跑 `basic` 前先点「🔄 重置 demo 数据」，避免表已存在报 FAILURE。
